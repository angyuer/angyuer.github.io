# 文章写作规范

本规范以阮一峰的[《中文技术文档的写作规范》](https://github.com/ruanyf/document-style-guide)
为基础，并针对 Hexo 个人博客做了调整。上游规范采用公共领域许可。

## 适用范围

- 技术、日记和项目频道的所有新文章必须遵守本规范。
- 旧文章逐步整理，不为了通过检查而改变原意。
- 机器能够稳定判断的规则由 `npm run check` 强制执行，其余规则由作者审阅。

## Front Matter

每篇文章必须包含以下字段。

| 字段 | 要求 |
| --- | --- |
| `layout` | 固定为 `post` |
| `title` | 2～80 个字符，不以句号、逗号、分号或冒号结尾 |
| `date` | 有效日期 |
| `updated` | 有效日期，且不得早于 `date` |
| `channel` | `tech`、`journal` 或 `project` |
| `categories` | 第一项必须与频道对应：技术、日记或项目 |
| `tags` | 1～8 个不重复的标签 |
| `summary` | 20～180 个字符，用一两句话说明文章内容 |
| `cover` | 本地 `/images/` 路径或 HTTPS 地址 |
| `featured` | 布尔值 |

项目频道还必须包含以下字段。

| 字段 | 要求 |
| --- | --- |
| `project_status` | `ongoing`、`completed` 或 `paused` |
| `project_period` | 项目时间范围，例如 `2026.07 - 至今` |
| `project_role` | 本人在项目中负责的范围 |
| `project_stack` | 1～8 项实际使用的技术或工具 |
| `project_links` | 1～4 个 HTTPS 或站内链接，包含 `label` 和 `url` |

## 文件名

- 文件名使用小写半角字母、数字和连字符，不使用空格、下划线或中文。
- 推荐形式为 `cocos-font-loading.md`。
- 纯中文标题通过快捷命令创建时，文件名自动使用日期和时间戳。
- 文章永久地址由 `abbrlink` 决定，源文件改名不得改变既有永久地址。

## 标题

页面模板已经使用文章标题生成一级标题，因此 Markdown 正文不得再写一级标题。

- 正文从二级标题 `##` 开始。
- 最深使用四级标题 `####`。
- 标题层级必须连续，不能从二级标题直接跳到四级标题。
- 下级标题不要重复上级标题的名称。
- 同级标题只有一项时，优先取消这一层级。
- 标题末尾不使用句号、逗号、顿号、分号或冒号。

## 文本与段落

- 中文与英文、中文与数字之间保留一个半角空格。
- 数字与英文单位之间保留一个半角空格，例如 `16 GB`。
- 一个段落只表达一个主题，中心句尽量放在段首。
- 段落推荐不超过四行，最多不超过七行。
- 优先使用短句、简单句、主动语态和肯定表达。
- 避免感叹语气、双重否定、模糊代词和堆叠形容词。
- 段落之间保留一个空行，段首不缩进。

## 数字与标点

- 阿拉伯数字使用半角形式。
- 中文句子使用全角中文标点，完整英文句子使用半角英文标点。
- 中文并列词使用顿号，最后一项优先使用“和”连接。
- 时间使用半角冒号，例如 `08:30`。
- 中文省略号使用 `⋯⋯`，不使用 `...` 或 `。。。`。
- 不连续使用多个感叹号。
- 数值范围使用 `～`、`—` 或“至”，两端都写明单位。

## 图片、链接与引用

- 新图片存放在 `source/images/posts/<文章标识>/`。
- Markdown 图片必须填写能够说明内容的 Alt 文本。
- 本地图片必须存在；外部图片和链接必须使用 HTTPS。
- 图片应优先使用 WebP 或 AVIF，并在入库前运行 `npm run optimize:images`。
- 引用第三方文字、代码或图片时必须注明作者和来源，并链接原文。
- 全文转载必须在文章开头明确标注作者、出处和原文地址。
- 链接文字应说明目标内容，不使用“点击这里”一类模糊文字。

## 频道结构

技术文章推荐使用：问题、环境、方案、实现、验证、参考资料。

日记文章推荐使用：记录、思考、接下来。

项目文章推荐使用：背景与目标、我的职责、方案、难点与取舍、结果、复盘、参考资料。

结构可以按内容删减，但不要保留空章节。

## 旧内容

`md文件的基本常用编写语法.md` 为迁移前的 Markdown 演示文章，正文需要展示多级标题，
暂时不执行正文标题检查。它仍然接受 Front Matter 和封面检查，后续重写时应移除例外。
